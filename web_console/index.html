      Artifact Center

      Read-only artifact workspace. Artifacts are discovered only from the active project's authorized publication roots (workspace/, evidence/, reports/) and the authoritative completion ledger. Previews are bounded per format, verified against the receipt hash, and render as inert text only; provenance names the producing round when a verified receipt binds the file — and says unbound when it does not. Nothing here can edit, rename, delete, or overwrite an artifact; the only action is feedback to Codex through the formal intervention surface.

      Step 1 — Project Goal + Inputs

      PROJECT_GOAL.md defines the destination, not Runtime routing internals: it should carry Objective, Context, Available Inputs, Required Deliverables, Constraints, Non-Goals, and Acceptance Criteria — and must not prescribe MESSAGE_ID values, NONCE values, claim/fence mechanics, or exact turn counts. Outputs must stay inside the supported publication roots (workspace/, evidence/, reports/); artifacts/ as an output root is rejected before bootstrap.

          Step 4 — Readiness / Preflight / Start

          Each specification check is reported separately: goal_loaded, goal_anchor, inputs_registered, project_type_valid, supervisor_config_valid, runtime_healthy, python_requirements, control_plane_v12, zcode_acknowledged, preflight — all required, all fail-closed.

          Start runs the documented bootstrap (start_project.py) and then the Runtime's own START_AGENT_SYSTEM.ps1 entry point, only if every readiness check passes; the request goes to the bounded /setup/start endpoint and answers SETUP_NOT_READY (nothing bootstrapped or started) otherwise. The bootstrap never overwrites an existing project or Goal Anchor.

          New Runtime from the supported release

          Creates a new isolated Runtime Root by copying this installation's supported release skeleton — product, control plane, profiles, Console, and documentation only. Never copied: projects, completion/claim/dispatch ledgers, STOP/attention flags, logs, registry data, credentials, or caches. The destination must not exist — nothing is ever overwritten, no created Runtime is started automatically, and a failed copy is rolled back. The source is this installation; the browser cannot name a source path or command.

          Creation is explicit, validated, and registered only after a complete validated copy.

            Human control

            Controls call the v1.2 Runtime entry points only. A mutation is never invented here and never edits authoritative Runtime files directly; the Runtime decides and reports the outcome.

            Safe Pause / Resume

            Resume clears the pause. The Runtime returns to RUNNING and the Orchestrator may start the next Supervisor turn. A HUMAN_REVIEW is not cleared by Resume — it needs a Human Decision below.

            Human intervention

            The intervention is queued for the next Supervisor turn (queued → delivered → consumed). Default: the current valid task may finish first.
