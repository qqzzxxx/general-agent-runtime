      Errors and warnings

        Human control

        Controls call the v1.2 Runtime entry points only. A mutation is never invented here and never edits authoritative Runtime files directly; the Runtime decides and reports the outcome.

        Safe Pause / Resume

        Pause Scheduling stops new Executor work from starting (for example during a quota shortage). The current valid task may finish, and a dispatched task that was not claimed yet is parked — not failed. Only the checkbox turns this into a high-risk interrupt of current work.

        Resume clears the pause. The Runtime returns to RUNNING and the Orchestrator may start the next Supervisor turn. Parked work from a scheduling pause continues automatically with a fresh authorized task — no extra human decision is needed after a quota pause. A HUMAN_REVIEW is not cleared by Resume — it needs a Human Decision below.

        Human intervention

        The intervention is queued for the next Supervisor turn (queued → delivered → consumed). Default: the current valid task may finish first.

        HUMAN_REVIEW — human decision required

        Why automation stopped (from the Runtime's own HUMAN_REVIEW record):

        View Full Reason

        Data and history are preserved. The flow is two steps: prepare the decision, then apply and continue. Applying commits HUMAN_REVIEW → SUPERVISOR_TURN through the audited Runtime helper; the Console then automatically resumes the Runtime through its documented START entry point so the Supervisor consumes the decision immediately. Before starting, a mechanical safety gate must prove, from the Runtime's own state, that the decision is applied, the resume event is persisted, and no STOP, live Orchestrator owner, or other start is in the way; if it refuses, the blocking reason and a one-click Resume are shown instead. Resume alone will not clear this state. Use only the Prepare → Apply decision flow below: "Submit intervention" is disabled while HUMAN_REVIEW is active because a queued intervention cannot resume the Runtime and must not substitute for the formal decision.

        Applying the decision transitions HUMAN_REVIEW → SUPERVISOR_TURN through the audited Runtime helper. It is bound to the exact state hash captured at prepare time; a stale or duplicated application fails closed and changes nothing. When the mechanical safety gate passes, the Console then automatically resumes the Runtime; if the gate refuses or the start fails, the decision stays applied and a one-click Resume is offered.

          Interrupt current task

          Revokes the current task's Runtime authority using the existing fencing (the task is retired and quarantined), preserves all historical records, and leaves the Runtime paused; future work requires fresh authorization. This is cooperative — it does not kill the Executor process, which stops at its next control boundary.

          The current task will be retired (authority revoked), the TO_ZCODE dispatch quarantined, and the Runtime paused. History is preserved. Resume when you are ready.

          Formal STOP

          STOP is terminal and different from Pause: the Orchestrator makes no new Codex calls after detecting it, and an ordinary Resume will not resurrect the stopped work — recovery needs the documented STOP path.               Step 4 — Readiness / Preflight / Start

              This step does three separate things, in order: readiness runs read-only checks against the stored draft and the Runtime; bootstrap (start_project.py) creates the project and its Goal Anchor; and start invokes the Runtime's own START_AGENT_SYSTEM.ps1 entry point. Nothing runs until you confirm, and each part fails closed.

              Each specification check is reported separately: goal_loaded, goal_anchor, inputs_registered, project_type_valid, supervisor_config_valid, runtime_healthy, python_requirements, control_plane_v12, zcode_acknowledged, preflight — all required, all fail-closed.

              Start runs the documented bootstrap (start_project.py) and then the Runtime's own START_AGENT_SYSTEM.ps1 entry point, only if every readiness check passes; the request goes to the bounded /setup/start endpoint and answers SETUP_NOT_READY (nothing bootstrapped or started) otherwise. The bootstrap never overwrites an existing project or Goal Anchor.
