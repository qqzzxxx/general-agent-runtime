# v1.4 Phase 9 — Supervisor Intelligence Efficiency

Phase 9 preserves the Phase 8 Outcome Owner and changes the default investigation
boundary: **Supervisor owns the decision, not the implementation investigation.**
The Supervisor still owns the user outcome, real constraints, current decision,
evaluation of results, and whether more work or verification is needed. It delegates
implementation discovery when the Goal and lightweight facts already justify work.

## Decision context and referenced deep context

[`supervisor_context.py`](../scripts/supervisor_context.py) now emits context version
3. It retains the complete canonical Goal, verified Goal Anchor block, current state
projection, current memory, sourced constraints, revisable assumptions, latest
decision, unresolved criteria, interventions, and new receipt evidence. Unknown
semantic fields, negative judgments and conflicting mirrors remain visible. Legacy
memory remains complete; only explicitly organized historical sections are deferred.
No model summarizer, relevance classifier, prefix cut, or new authority is introduced.

The `REFERENCED DEEP CONTEXT` block names original state/memory, committed receipt,
domain guidance, policy and special output contracts. Implementation and evidence
paths already named in the Goal/state/receipts are references too. References are
pointers, not a reading checklist. The builder no longer opens reference-only files
to calculate presentation-only sizes/hashes, or rereads the state already supplied by Runtime.
It still measures and hashes the exact delivered prompt. Goal verification and
committed-receipt selection remain in their existing authoritative Runtime paths.
A missing reference must be established as missing by inspection when it matters;
the prompt does not assert that every pointer is present or verified.

The canonical [Supervisor contract](../control/CODEX_SUPERVISOR_RUNTIME.md) explicitly
requires the cheapest sufficient decision context. It forbids deep implementation
reading merely to enrich the first dispatch. The SOFTWARE_ENGINEERING guide now
asks the Supervisor to evaluate submitted diff/run evidence and inspect further
when a consequential claim remains uncertain. The Executor owns implementation
investigation and solution choice. HIGH autonomy remains preferred for open-ended
product work. Information architecture, wording, navigation, DOM and implementation
remain revisable unless a sourced requirement constrains them.

Deep inspection remains necessary for material ambiguity, conflicting evidence,
suspected regression or scope drift, insufficient result evidence, FV failure or
disagreement, and a high-risk interface constraint that must be established before
delegation. Relevant history is still required for method/retry questions and AUDIT.
The Supervisor identifies the decision question, inspects the relevant evidence,
and stops reading when that question is resolved. Unresolved consequential uncertainty
requires more evidence, more work or Human Review; lower cost never implies success.

The Supervisor may reuse adequate submitted evidence to judge an outcome. It must
still inspect consequential visual/interaction evidence for UI results and select
required independent FV. Phase 9 does not substitute an Executor assertion for
verification or ask the Supervisor to rerun the entire implementation investigation.

## Targeted inspection

[`supervisor_inspect.py`](../scripts/supervisor_inspect.py) is a read-only CLI:

```powershell
python scripts/supervisor_inspect.py --path projects/example/interface.md --reason interface_constraint --offset 0 --limit 8192
```

Run it from the active Runtime Root and obey the existing project scope. Reasons
are `ambiguity`, `conflict`, `regression`, `scope_drift`, `insufficient_evidence`,
`fv_disagreement`, `interface_constraint`, `history`, `audit`, and `contract`.

The helper reads at most the requested byte slice (default 8 KiB, maximum 64 KiB).
It returns the resolved Runtime-relative path, actual raw bytes read, byte offsets,
file size, whether more bytes remain, a hash of the slice, and a change-during-read
indicator. UTF-8 decoding uses replacement for invalid or split characters; offsets
and hashes describe raw bytes. A slice hash is not a full-artifact hash or proof of
correctness. Missing files and invalid ranges return an explicit error. Resolved
paths outside the Runtime Root, including symlink escapes, are rejected. It writes
no telemetry or project files and can be used in the read-only Human Decision turn.

This is an inspection convenience, not an OS sandbox or a new capability grant.
Existing project and host restrictions still apply. Native inspection remains
available for images, unsupported evidence and cases where the helper is inadequate.
There is no hard read quota that would make the Supervisor blind.

## Per-turn measurement

[`supervisor_intelligence.py`](../scripts/supervisor_intelligence.py) attaches small
diagnostics to the existing fresh Codex invocation capture. Prompt construction
does not include telemetry histories or model-authored usage estimates.

| Measurement | Source and limits |
| --- | --- |
| Prompt characters / UTF-8 bytes / SHA-256 | Exact string sent on stdin; includes section sizes. Excludes host instructions, tool schemas and later tool context. |
| Builder reads / bytes | Files opened by the context builder itself. Excludes upstream Goal verification/profile loading and model-initiated reads. |
| Input/output/cached input tokens | Existing allowlisted `turn.completed.usage` transport capture, bound to the fresh invocation. Missing provider fields remain unavailable. |
| Uncached input | `input_tokens - cached_input_tokens`, only when both provider counters exist and form a valid nonnegative subset. Labeled `input_minus_cached`, not an additional provider-reported counter. |
| Turn duration | Monotonic time around provider capture, including bounded stdout drain. Recorded on ordinary exit, nonzero exit and timeout. Excludes prompt construction and later decision commit. |
| Targeted read attempts / reads / approximate bytes | Observed completed command items invoking the helper, with parsed helper output and deduplicated item IDs. Counts repeated intentional reads separately. |

The immutable diagnostic sidecar lives beside existing usage captures at
`control/supervisor_usage/<turn-id>.invocation.intelligence.json`. It is bound to
the existing invocation record hash. On normal finish or recovery, Runtime merges
`targeted_reads` and `input_cache` into the turn's `context_manifest` and restores
the recorded duration. The existing turn-record schema and usage authority remain
unchanged. Exact prompt measurements survive recovery even if no decision commits.
If the process is killed before the diagnostic sidecar can be published, diagnostics
may be unavailable; no duration or read count is reconstructed from model prose.

Read diagnostics explicitly say `coverage: helper_only` and
`source: observed_helper_command_outputs`. They are cooperative diagnostics, not an
exhaustive or tamper-proof filesystem audit. Ordinary shell/image reads are outside
this count. A completed command event that cannot be parsed, an oversized stream
item, incomplete invocation, or unfinished drain marks coverage incomplete. Observed
zero helper reads does not mean zero total investigation. When coverage is incomplete,
the captured counts are partial observations, not totals. Commands, evidence content,
paths, credentials and raw tool streams are not persisted in the diagnostic sidecar.
The bounded set stores at most 4,096 completed helper item IDs while capturing.

Diagnostic storage errors, invalid sidecars and missing captures do not authorize,
reject or consume a decision. Provider usage still comes exclusively from its
separate validated transport receipt; command output cannot supply token counts.
Read-only Supervisor turns do not need permission to write telemetry because the
Runtime observer publishes it outside the model process.

[`measure_supervisor_efficiency.py`](../scripts/measure_supervisor_efficiency.py)
compares the frozen Phase 8 context builder/contract/guide against Phase 9 using
identical Goal, state, lightweight memory and profile selection. Paths, time and
nonce are normalized for comparison. It measures actual file reads at the builder
boundary. Source code is present in the fixture but neither builder reads it.

```powershell
python scripts/measure_supervisor_efficiency.py --output evidence/v1.4-supervisor-intelligence-efficiency/generated
```

| B3 initial decision context | Phase 8 | Phase 9 |
| --- | ---: | ---: |
| Prompt characters, LF normalized | 15,615 | 16,043 |
| Prompt UTF-8 bytes | 15,619 | 16,047 |
| Builder file reads | 6 | 3 |
| Builder bytes read | 10,796 | 8,454 |
| Implementation bytes read by builder | 0 | 0 |

Builder reads fall by 50% and builder bytes by 21.69%. The added demand-driven policy
and helper guidance increase this small bootstrap prompt by 428 characters (2.74%).
This phase primarily changes the investigation policy and makes its cost observable;
it does not claim a measured live intelligence-cost reduction. Phase 8 already
avoided source reads inside its prompt builder. A matched live run would be needed
to establish fewer model-initiated reads, lower provider tokens, lower latency or
better model quality. Those improvements and the historical live B3 deep-read count
are explicitly null in the comparison output.

The [authored Phase 9 proposal](../evidence/v1.4-supervisor-intelligence-efficiency/generated/b3-phase9-authored-proposal.json)
uses only the Goal and input names. It preserves desired outcome, quality bar, a
Goal-sourced preservation constraint, current facts, revisable assumptions and HIGH
autonomy. It asks the Executor to establish the original information/actions and
substantiate preservation, render and exercise the result, and improve weaknesses.
It does not need a Supervisor-authored handler/component inventory. Runtime validates
the proposal without any Supervisor implementation read. This is an authored contract
regression example, **not a sampled Supervisor decision or live quality experiment**.

## Validation and preserved boundaries

The Phase 9 tests establish both sufficiency and escalation:

- B3 bootstrap builds without opening source or reference-only policy/guidance files;
  the outcome-oriented HIGH proposal validates without freezing implementation.
- A synthetic public-interface requirement is established by a 37-byte targeted
  slice, then added as a sourced hard constraint while HIGH autonomy remains intact.
- Deferred method-failure history is absent from the default view but accessible to
  resolve a retry question. Current uncertainty and the retry limit remain visible.
- Conflicting decision mirrors, scope-drift concerns, missing interaction evidence,
  negative/disagreeing FV results and AUDIT obligations survive presentation.
- Range limits, missing files, root escapes, read-only CLI behavior, duplicate events,
  malformed outputs, partial usage, missing cached counts, timeout durability,
  replay and invalid sidecars are covered. The orchestrator test checks exact prompt
  measurement, cache derivation and the bounded combined turn manifest.
- Existing provider tests exercise recovery, failure/timeout usage preservation and
  resistance to model-authored usage. Fresh Runtime skeletons require the three
  Supervisor context/inspection/intelligence modules together.

Goal Anchor, current-state preservation, control revision, pause/interrupt,
exactly-once intervention consumption, ordinary task construction, archive/seal,
registration, permanent claims, stale-worker fencing, publication, completion
commit/consume/seal and retry budgets retain their existing authority. FV claim
selection, fixed standards, negative judgments and acceptance binding are unchanged.
The full-wire FV and Human Decision contracts remain mandatory when applicable.

The final full repository regression completed **1,513 tests in 464.686 seconds,
with 3 skips and no failures** (process exit 0). Focused checks passed 118 tests;
the post-fix integration run passed 66. The initial full run exposed missing module
files in HTTP creation fixtures and the need to retain an unconditional role-boundary
reminder when the contract is stubbed; both were fixed before the complete rerun.
Windows socket/subprocess cleanup warnings remain in the log without failing the
suite. Commands and results are recorded in
[`validation.txt`](../evidence/v1.4-supervisor-intelligence-efficiency/validation.txt)
and the [full regression log](../evidence/v1.4-supervisor-intelligence-efficiency/full-regression.txt).

Work stops after **Phase 9**. No deployment or live experiment was performed.
